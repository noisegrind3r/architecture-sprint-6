Проектирование продажи ОСАГО

  Для реализации нового продукта продажи ОСАГО предлагается следующее решение.
    
    - Создание нового сервиса osago-aggregator для получения данных о страховках из сторонних сервисов. У сервиса будет собственная БД Postgres для хранения информации о полученных ранее страховках и реализации паттерна Transactional Outbox.
    
    - Взаимодействие с сервисом core-app будет в асинхронном виде через брокер сообщений Kafka. После создании заявки пользователем, сервис core-app отправит событие "заявка создана". Сервис osago-aggregator будет подписан на это событие и после получения сообщения, отправит параллельные запросы в синхронном режиме к страховым компаниями и запишет ответ от каждой из них в базу данных. После чего, независимо по каждой страховой компании, отправит событие в брокер сообщений "Данные о страховке получены", которое обработает сервис core-app. В случае, если какой-то из сервисов страховых компаний, возвращает ошибку или отвечает больше 60 секунд, сервис osago-aggregator выполнит поиск в БД по ранее созданным значениям с заданными параметрами поиска и, в случае успеха, вернет в ответе старое значение с пометкой, что данные могут быть неактуальны. При отправке события в брокер сообщений, каждый сервис будет использовать паттерн Transactional Outbox для большей отказоустойчивости.

    - Взаимодействие сервиса core-app с web-приложением, в части получения информации по ОСАГО, будет выполняться по протоколу WebSockets. После получения запроса о новой заявке со стороны web-приложения, и получения ответа от osago-aggregator, сервис core-app будет отправлять ответ по каждой страховой компании через WebSockets пользователю в web-приложение.

    - API приложения core-app:
      - async producer "insurance_request_created" 
      - async consumer "insurance_data_received" 
      - Websockets SubscribeMessage "create_insurance_request" 
      - Websockets SendMessage "insurance_data" 

    - API приложения osago-aggregator:
      - async producer "insurance_data_received"
      - async consumer "insurance_request_created"

    - применение паттернов отказоустойчивости:
      - Rate Limiter для сервиса core-app на запрос получения заявок на ОСАГО, чтобы не перегрузить запросами внешние и внутренние сервисы
      - Timeout для osago-aggregator при ожидании ответа от внешних сервисов страховых компаний 
      - Circuit Breaker при запросах к внешним системам, чтобы не отправлять запросы к неработающим сервисам

    - продукт InsureTech использует горизонтальное масштабирование и имеет несколько задеплоиных экземпляров сервисов, поэтому, для того чтобы сообщение о лицензиях получил тот core-app сервис, который поддерживает открытое соединение через WebSockets с web-приложением, потребуется использовать уникальный routing-key для каждого запроса ОСАГО в событиях брокера сообщений.
