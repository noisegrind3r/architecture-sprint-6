Проектирование технологической архитектуры

1. Определите стратегию масштабирования и отказоустойчивости

  В данном решении больше подойдет горизонтальная архитектура масштабирования за счет параллельной обработки запросов и дополнительной отказоустойчивости, тогда как вертикальная потребует не прогнозируемо большого количества ресурсов сервера и не решит всех проблем с нагрузкой. Для ещё большей отказоустойчивости и большей доступности системы предлагается использование дополнительных зон доступности.

2. Проработайте конфигурацию развёртывания приложения в Kubernetes.
  
  Для деплоя приложения в разных зонах доступности предлагается использование независимых кластеров в каждой площадке, чтобы избежать единой точки отказа, получить более высокую производительность в точке доступа и меньшие задержки при репликации данных.

3. Спланируйте балансировку нагрузки

  Для балансировки нагрузки предлагается использовать GSLB (Global Server Load Balancer), который направляет запрос на ближайший и самый быстрый к пользователю ЦОД. Балансировщик периодически определяет доступность ЦОД с помощью вызова Health Check. Если ближайший ЦОД недоступен, то запрос направляется на другой ЦОД, пусть и не такой быстрый.

4. Определите наиболее подходящую фейловер-стратегию.

  На каждом ЦОД предлагается использовать фейловер-стратегию Active-Passive, один контейнер с приложением доступен в активном режиме, а другой в пассивном для экономии ресурсов. В случае выхода из строя активного контейнера, в то время, пока поднимается резервный, балансировщик GSLB перенаправит запросы на другой ЦОД.

5. Определите конфигурацию базы данных

   Обеспечить репликацию данных между ЦОД предлагается с помощью шаблона конфигурации Patroni, в который включены HAProxy для балансировки запросов и pgBackRest для резервного копирования. Для ускорения получения данных, предлагается с помощью конфигурации БД Master-Slave, с одной репликой БД для записи и двумя для чтения. В последующем, можно будет увеличить количество реплик для чтения.

6. Определите, будете ли вы применять шардирование БД
  
   Шардирование данных пока не вижу необходимости использовать.
